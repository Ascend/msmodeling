# AI 执行授权规范

## 1. 执行模式

### guided

默认模式。以下阶段开始前必须获得用户确认：

- Issue 最终草稿提交
- 需求分析结论
- 方案选择和开发计划
- 远端写操作
- 代码实现范围变化
- CI 修复方案
- PR 从 Draft 切换为 Ready

### autonomous

用户明确授权后，AI 可在约定仓库、Issue、分支、目标和时间范围内连续推进。授权必须记录到 Issue 或 PR
评论。未明确范围的“自动执行”只覆盖当前 Issue，不扩展到其他资源。

## 2. 硬停止点

无论执行模式如何，出现以下情况必须停止并请求人工决策：

- 需求、仓库、目标分支或公共行为发生实质变化。
- 发现凭证、隐私数据、安全漏洞细节或其他敏感信息。
- 需要绕过测试、屏蔽门禁或降低验收标准。
- 需要关闭 Issue、强制推送、强制测试通过、审批或合并。
- `spec/`、代码和远端事实互相冲突。
- 涉及破坏性或不可恢复操作。
- 需要新的权限、外部协调或用户未授权的系统。

## 3. 人工介入

用户可随时要求：

- 暂停；
- 修改计划；
- 重新执行某个门禁；
- 跳回前一阶段；
- 由人工接管；
- 终止。

暂停或接管前，AI 必须记录当前阶段、已完成证据、未完成事项、工作树状态和恢复命令。

## 4. 失败处理

- 可重试的只读操作允许有限重试。
- 写操作失败后必须先确认远端是否已成功，避免重复创建。
- 无法确认幂等性的写操作不得盲目重试。
- 质量门禁失败必须修复或形成明确阻塞结论，不能记为通过。
