# Agent 方式：PD 分离寻优

本文档介绍通过 Agent 方式完成 vLLM PD 分离寻优的完整流程，涵盖 Agent 安装启动、任务说明编写、寻优过程确认与结果查看，适用于需要自动寻优 PD 配比与参数的运维人员。先完成 [PD 分离寻优公共环境准备](optix_pd_environment.md)。本文以四台机器为例，A 为控制端。准备支持读取文件、执行命令和持续监控任务的 Agent 工具，以及可访问的模型服务。

## 1. 安装并启动 Agent

在 A 节点的 `optix-pd` 容器内安装并启动 Agent；B、C、D 不需要安装。

选择支持读取文件、执行命令和持续运行任务的 Agent 工具，并配置可访问的模型服务，例如 [msAgent](https://gitcode.com/Ascend/msagent) 或 [OpenCode](https://opencode.ai/docs/)。以下以 OpenCode 为例，在安装 OptiX 的环境中执行：

```bash
cd /workspace/msmodeling
source .venv/bin/activate
opencode
```

仓库路径按实际情况替换。知识库缺失时按 Skill 提示准备。

## 2. 告诉 Agent 要做什么

启动 Agent 后，复制下面的任务说明，把 **`[需要填写：…]`** 替换为实际信息。不清楚的内容可以留空，请 Agent 协助确认。

```text
请读取本仓库的 .agents/skills/optix-assistant/SKILL.md，使用 Agent 模式进行 vLLM PD 分离寻优，使用 AISBench 测评。

机器：[需要填写：四台宿主机的 IP、SSH 账号和端口]。
容器与设备：[需要填写：每台机器的容器名称和可用设备编号]。
模型：[需要填写：容器内模型路径和服务模型名]。
负载：[需要填写：数据集或输入长度、输出长度、请求数和并发]。
目标：[需要填写：吞吐、TTFT 和 TPOT 要求]。
预算：[需要填写：最多实测次数和总时长，包含基线和复测]。

请检查 SSH 连接，准备缺失的 PD 插件和 AISBench，展示配置和计划供我确认。
执行中汇报进度，结束后提供最佳配比、参数、与基线的对比和部署复现文件。
```

**示例**：以下地址和负载仅供参考，使用前请替换成自己的实际信息。

```text
请读取本仓库的 .agents/skills/optix-assistant/SKILL.md，使用 Agent 模式进行 vLLM PD 分离寻优，使用 AISBench 测评。

机器：A 为 192.0.2.10，B 为 192.0.2.11，C 为 192.0.2.12，D 为 192.0.2.13；SSH 账号为 worker，端口为 22。
容器与设备：四台机器的容器均为 optix-pd，每台可用设备编号为 0～15。
模型：容器内路径为 /mnt/share/weights/DeepSeek-V4-Flash-w8a8-mtp，服务模型名为 dsv4。
负载：使用 GSM8K 数据集，输出长度 256 token，请求数 96，并发 24。
目标：TTFT 不超过 3000 毫秒，TPOT 不超过 50 毫秒，在满足时延目标的前提下提高吞吐。
预算：最多 24 次实测、总计 4 小时，包含基线和复测。

请检查 SSH 连接，准备缺失的 PD 插件和 AISBench，展示配置和计划供我确认。
执行中汇报进度，结束后提供最佳配比、参数、与基线的对比和部署复现文件。
```

服务模型名可自定义，由 Agent 保证服务端与压测一致。不了解延迟目标时，可改为“请先测基线，解释结果后与我确认目标”。

其余准备和执行由 Agent 完成，信息不足时会集中询问。按提示选择交互式模式，可逐轮确认方案；希望在预算内自动推进时，可在任务说明中补充“采用全自动模式”。

## 3. 确认任务，等待 Agent 寻优

Agent 检查环境后，会展示配置和执行计划。核对以下内容并在对话中确认：

- 使用的机器、可用卡和模型是否正确。
- 请求长度、请求数、并发是否符合本次业务。
- 性能目标、时间和次数预算是否符合预期。

确认后，**服务启动、基线测量、配比与参数调整、压测、复测和结果导出均由 Agent 完成**。无需另开终端启动服务、修改配置或运行压测命令。交互式模式下，Agent 会在需要确认下一组方案时提示你。

本案例使用 AISBench 测量完整 PD 部署的表现，根据端到端吞吐、延迟和成功率选择方案，不需要额外准备 P、D 单侧测量环境。

执行期间可直接与 Agent 对话：

| 需要做什么 | 可以这样说 |
|---|---|
| 查看进度 | “汇报当前进度、最佳结果和剩余预算。” |
| 暂停 | “清理当前任务后暂停，保留结果。” |
| 恢复 | “继续之前的寻优，请先检查环境和剩余预算。” |
| 遇到异常 | “请分析这次失败，告诉我原因及是否需要管理员协助。” |

Agent 会保留任务记录。若更换会话，将之前的任务目录交给新会话继续处理；无需自行编辑记录或清理服务进程。

## 4. 查看结果和复现方案

寻优结束后，Agent 通常会给出报告和部署文件路径。找不到时可询问：

```text
请告诉我本次寻优的运行目录、最终报告、每轮结果及最佳方案部署文件的路径。
```

结果通常位于仓库下 `.agent_optimizer/runs/<run_id>/`，自定义目录以 Agent 给出的路径为准。

| 想看什么 | 文件或目录 |
|---|---|
| 最终报告 | `final_report.md`，具体路径以 Agent 提供的为准 |
| 每轮吞吐和延迟 | `results.round-N.json`，在 `trials` 中查看各候选的 `performance`；`generate_speed` 为输出 token 吞吐，`throughput` 为请求吞吐 |
| 每轮进度 | `progress.round-N.json` |
| 最佳方案和部署文件 | `best_result.json` 和 `best_deployment/` |

文件在对应步骤成功后生成；找不到时请 Agent 检查任务和导出状态。

完成后，Agent 会给出总结及报告路径。打开 `final_report.md`，重点查看：

| 内容 | 看什么 |
|---|---|
| 最佳方案 | P/D 配比、设备分配和服务参数 |
| 性能表现 | 吞吐、首 token 延迟（TTFT）、后续 token 延迟（TPOT）、请求成功率 |
| 与基线对比 | 同一业务负载下是否提升，是否满足目标 |
| 复测结论 | 最佳方案是否经过独立复测，结果是否稳定 |
| 完成范围 | 实际耗时、测量次数，以及未完成项及原因 |

完成的判断是：有成功的完整 PD 实测、基线与胜出方案的独立复测结论，以及报告和可复现的部署文件；性能是否达标单独说明，不预设提升比例。

报告应逐项列出“推荐 P/D 配比、基线与推荐方案的吞吐/TTFT/TPOT、复测结论、未完成项”。这里不提供示意性能数值，实际数据以本次测量为准。

部署文件保存在 `best_deployment/`，具体路径由 Agent 提供。没有完成复测时，报告应明确说明，不能把单次最好成绩当成稳定收益。

需要复现时，对 Agent 说：“请根据导出结果在原环境复现最佳方案，开始前确认资源可用。”Agent 会准备具体方案，确认后执行部署和验证，无需手工复制脚本或逐台启动服务。

遇到无法自动解决的问题，让 Agent 整理错误摘要、环境信息和相关日志，再联系管理员或支持人员。不要在对话中发送 SSH 私钥或访问令牌。
